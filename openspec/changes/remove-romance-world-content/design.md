## Context

恋爱世界实现主要以未跟踪的新目录存在，但已经接入多个被大量修改的核心文件。工作树同时承载其他开发中的变更，直接 `git reset` 或整体恢复文件会破坏无关工作。删除还涉及 `/api/chat`、prompt、唯一 Zustand store 与存档类型，因此必须按依赖边界清除，并用类型检查和契约测试确认没有悬空引用。

## Goals / Non-Goals

**Goals:**

- 删除所有只服务“知夏之梦”或恋爱世界的实现、测试、资源和规划资产。
- 将创建、开场、游玩、聊天与持久化路径收敛回暗月单世界。
- 保持暗月的 SSE、DM JSON、状态提交、epistemic filtering、validator 与 world tick 契约。
- 保留工作树中与目标内容无关的现有改动。

**Non-Goals:**

- 不重构 `/api/chat`、`page.tsx` 或 `useGameStore` 的既有架构。
- 不删除暗月 canon 中明确约束角色“不是恋爱关系”的防误写文本。
- 不修改数据库 schema、analytics 口径、认证、配额或部署配置。
- 不承诺旧恋爱世界本地存档继续可玩；该世界已被产品移除。

## Decisions

1. **定向删除而非 Git 整体回退。** 先删除独立目录和文件，再从共享文件中移除 import、类型、状态、条件分支与 UI 接线。替代方案是回退引入提交，但目标代码尚未形成独立提交且工作树有大量无关变更，风险不可接受。
2. **暗月单世界成为确定性默认值。** 删除世界选择和恋爱创建内容，不保留隐藏开关或死代码，以免未来被意外重新启用。
3. **从边缘向核心清理。** 先识别叶子模块，再处理共享入口；每轮用 TypeScript/ESLint 暴露残留引用。对于核心文件，仅编辑与目标符号直接相关的 hunk。
4. **存档采用宽松遗留兼容。** 从当前状态与快照类型中删除目标字段，不新增迁移写回；旧对象的额外 JSON 字段由运行时忽略。暗月必需字段与 `skipHydration` 保持不变。
5. **聊天契约不变。** 删除恋爱 prompt packet、validator 与 state delta 字段，不改变 SSE 帧格式、最终收口顺序或 AI task routing，因此不新增 slow lane、重试或首字前工作。
6. **验证分层。** 全局名称/路径扫描用于检查残留；运行相关 unit/contract、`npx eslint .`、构建或类型检查确认依赖完整性；移动端 `/play` 用现有 E2E 尺寸覆盖验证暗月入口。

## Risks / Trade-offs

- [共享文件中的目标改动与无关改动交织] → 逐 hunk 编辑并在每次修改后检查 diff，不整体恢复共享文件。
- [删除通用关系字段可能破坏暗月 NPC 系统] → 只删除明确由恋爱世界新增的状态和 UI；暗月已有的 trust/fear/favorability 等通用字段保留。
- [文字扫描存在“非恋爱”暗月 canon 误报] → 对每个残留人工分类；暗月防误写约束加入允许清单。
- [旧恋爱存档无法继续] → 这是世界删除的预期破坏性结果；应用回到暗月默认流程且不得崩溃。
- [全量验证受现有脏工作树失败影响] → 区分本变更引入的失败与预先存在的问题，并记录完整命令和证据。

## Migration Plan

1. 删除独立的内容、UI、引擎、测试、benchmark、设计文档与旧 change。
2. 清除共享入口中的目标 import、分支、字段和样式。
3. 运行残留扫描与静态/自动化验证，修复悬空引用。
4. 将本 change 的 delta spec 同步为“暗月单世界”主规范；是否归档由后续收口流程决定。

回滚时只反向恢复本 change 的定向 diff，不回退工作树中的其他修改。

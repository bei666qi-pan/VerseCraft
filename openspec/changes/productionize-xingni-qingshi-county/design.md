## Context

青石县现有实现将地点、NPC、敌人和最小玩法集中在三个文件中，`world_delta.action` 由纯函数重算并通过既有 turn commit 写入唯一 store。这一基线已证明世界隔离和纵切可行，但状态缺少版本、任务、日程、伤势和幂等语义，内容 packet 也无法支撑长程游玩。

## Goals / Non-Goals

**Goals:**

- 交付 3–5 小时、45–70 个有效回合的五章首图，并保证每条权威进度来自登记状态机。
- 让三种灵根、三艺路线、硬核失败与救济恢复形成可平衡、可重放、可自动测试的系统。
- 保持一条 `/api/chat`、一个 store、既有 SSE/final/analytics 契约和暗月兼容。

**Non-Goals:**

- 不开放青云渡，不建设高阶修仙或多人系统。
- 不把通用回合工作流重构为 agent 协商系统，不让 narrative 成为状态源。
- 不在热路径增加 DB 写入、LLM 复核或重型随机模拟。

## Decisions

### 1. 内容包按域拆分并通过总 manifest 汇合

地图/NPC 保留在 `qingshiContent`，任务和事件、物品经济、权威状态与裁决分别成为独立纯数据/纯函数模块，总 manifest 供 prompt、seed、validator 和 UI 消费。相比继续扩张单文件，该方案减少热入口耦合，又避免建立平行 registry。

### 2. 状态升级为可归一化的 v2 判别式对象

`XingniTaichuState` 保留所有 v1 根字段并添加 `schemaVersion: 2` 及可序列化子状态。所有读取先经 `normalizeXingniState`；旧存档根据已有修为、凭证和试炼状态推导等价任务阶段，不补发物品。相比提升 RunSnapshot 主版本，此方案对云端和旧消费者影响更小。

### 3. 统一 action envelope，但兼容旧最小 action

登记行动统一包含 `actionId`、`type`、`targetId/locationId` 和 `idempotencyKey`。裁决器根据状态、地点、背包和登记内容重算结果，并在有限 `processedActionIds` 中防重；旧 E2E/模型产生的 v1 action 先规范化为兼容 action。未知 ID fail closed。

### 4. 确定性风险而非模型随机

战斗、炼制和试炼结果由稳定 hash（存档作用域、action id、尝试次数、灵根/准备）映射到结果档位。灵根只改变阈值和成本；所有路线都存在非专长解法。模型只收到已裁决结果，不参与成功率、损失或掉落。

### 5. 重伤回退与六步救济构成反软锁底线

失败最多扣除 25% 非保护灵石和一组普通材料，关键物品、任务进度、凭证、地图与配方不丢。重伤送回客栈；无钱时可接受固定救济委托，等待/休整/采集/提交形成不超过六步的恢复路径。所有服务错时均可等待、预约或支付替代成本。

### 6. Prompt 只传当前切片

stable prompt 声明叙事、权限和权威边界；动态 packet 仅包含当前地点、时段、在场 NPC、当前目标、可用服务、登记行动和受限状态摘要。完整任务图与 sealed 事实不进入每回合 prompt，既控制 TTFT，也降低泄密风险。

### 7. UI 是现有动作链的确定性投影

星逆面板展示目标、伤势、时间、在场 NPC 和服务，按钮仍提交现有自然语言 action，由模型候选和服务端 guard 收口。暗月导航与 test id 不变；星逆新增稳定 test id 供三尺寸 E2E。

### 8. 图鉴目录、自动捕获与头像全部按世界分流

移动图鉴从当前 `worldId` 选择目录：暗月继续使用原 NPC/异常与楼层筛选，星逆只使用青石县八名固定 NPC，并由权威日程投影当前位置。叙事自动捕获和 ID 名称兜底共享同一登记清单，避免出现目录正确但无法解锁的半套实现。星逆头像使用独立资源路径和明亮东方玄幻视觉体系，不覆盖或复用暗月头像。

## Risks / Trade-offs

- [长程内容让 prompt 变大] → 只注入当前任务和可见切片，完整内容留在注册表/DB。
- [客户端 digest 可伪造] → 延续候选模型，服务端只接受登记 action 并重算；幂等键与当前状态共同校验。
- [确定性 hash 被玩家预测] → 目标是公平可重放而非博彩安全；阈值不向正文暴露，关键任务均有准备性保底。
- [旧 action 没有幂等键] → 用规范化 action fingerprint 生成兼容键，同时限制历史集合大小。
- [硬核损失导致流失] → 不丢关键进度，提供清晰损失反馈和六步救济链。
- [NPC 日程造成等待摩擦] → UI 显示时段与下次在场时间，并提供预约/等待替代。
- [多世界共用图鉴组件造成内容串台] → 目录、未读统计、自动捕获和头像解析均显式接收或派生当前世界，并保留暗月默认兼容行为。

## Migration Plan

1. 部署 v2 类型、内容与归一化函数，世界开关保持关闭；读取旧存档时内存迁移并在下次保存写回。
2. 幂等 seed 新增任务、事实、物品和 NPC 日程；验证所有 chunk 均带星逆/青石作用域。
3. 部署裁决、prompt 和 UI，执行暗月合同、星逆三路线 E2E、迁移和反软锁检查。
4. 内部灰度后逐步开启既有世界开关；监测请求完成、回合提交、validator issue 和世界作用域错误。
5. 回滚仅关闭开关并回退读取行为；v2 字段保持向后兼容，不删除存档或 seed。

## Open Questions

无。生产数值、任务阶段和失败规则以本 change 的确定性内容包为事实源，后续平衡调整通过新 change 版本化。

## ADDED Requirements

### Requirement: World Director pipeline is defined as a LangGraph StateGraph

The World Director main pipeline (`runWorldEngineTick`) SHALL be implemented as a LangGraph `StateGraph<WorldDirectorGraphState>` with typed state, deterministic nodes, and conditional edges.

The graph SHALL consist of the following nodes in sequence: `load_context`, `build_messages`, `run_reasoner`, `parse_delta`, `validate_plan`, `run_critic`, `apply_social_gm`, `write_outputs`, `compute_next_state`, `build_director_hint`.

Each node SHALL be a pure async function `(state: WorldDirectorGraphState) => Promise<Partial<WorldDirectorGraphState>>` that maps 1:1 to an existing business logic function from `src/lib/worldEngine/`.

Conditional edges SHALL route based on node output:
- `load_context` failure → `END` with `hasPlan: false`
- `run_reasoner` failure → retry once, then fallback with `hasPlan: false`
- `parse_delta` invalid JSON → repair once, then skip tick with `hasPlan: false`
- `validate_plan` violation → continue but set `planConfidence: "degraded"`
- `write_outputs` failure → rollback

#### Scenario: Successful World Director tick through graph

- **WHEN** `graph.invoke()` is called with valid `WorldEngineTickPayload`
- **THEN** all nodes execute in order and produce a `WorldDirectorGraphState` with `hasPlan: true` and `planConfidence: "normal"`

#### Scenario: load_context failure short-circuits graph

- **WHEN** `load_context` node throws or returns `{ loadError: "DB unavailable" }`
- **THEN** the graph routes to `END` with `hasPlan: false` and `planConfidence: "none"`

#### Scenario: run_reasoner retries then falls back

- **WHEN** `run_reasoner` node fails twice
- **THEN** the graph routes to `END` with `hasPlan: false` and empty plan, allowing the writing agent to operate autonomously

### Requirement: Graph output carries hasPlan signal for two-phase behavior

The graph output `WorldDirectorGraphState` SHALL include a `hasPlan: boolean` field indicating whether a valid director plan was generated.

When `hasPlan` is `false`, the writing agent (DM Agent) SHALL operate autonomously without director guidance.

When `hasPlan` is `true`, the generated `directorHintBlock` SHALL be injected into the writing agent's system prompt as directional guidance.

#### Scenario: Writing agent operates autonomously when no plan exists

- **WHEN** graph output has `hasPlan: false` and the next player turn begins
- **THEN** `promptAssembly` does NOT inject `directorHintBlock` into the DM system prompt, and the writing agent generates narrative freely

#### Scenario: Writing agent follows plan when plan exists

- **WHEN** graph output has `hasPlan: true` and `directorHintBlock` contains a valid direction block
- **THEN** `promptAssembly` injects `directorHintBlock` into the DM system prompt, and the writing agent SHALL follow the stated direction (phase, progression, key event types) while freely creating specific dialogue and descriptions

### Requirement: directorHintBlock is a directional constraint, not a fact source

The `directorHintBlock` SHALL contain only directional guidance: current story phase, progression direction, key event types, pacing requirements, and prohibitions.

The `directorHintBlock` SHALL NOT contain specific dialogue, scene descriptions, NPC reactions, or concrete narrative facts. Those SHALL be generated by the writing agent.

The `directorHintBlock` SHALL include an explicit instruction to the writing agent that it should use the guidance as direction but create specific content independently.

#### Scenario: directorHintBlock contains only directional content

- **WHEN** `build_director_hint` node generates the hint block
- **THEN** the output contains fields like `phase`, `direction`, `key_event_type`, `pacing`, `prohibitions` but does NOT contain narrative snippets, dialogue, or specific scene descriptions

#### Scenario: Writing agent creates facts independently within direction

- **WHEN** `directorHintBlock` specifies "引导玩家前往旧图书馆" as direction
- **THEN** the writing agent writes the specific scene—library description, NPC dialogue, atmosphere—based on game state and character profiles, not by copying from the hint

### Requirement: Actor Simulation is defined as a LangGraph subgraph

The Actor Simulation pipeline SHALL be implemented as a standalone LangGraph `StateGraph<ActorSimGraphState>` and invoked as a nested subgraph from the World Director main graph.

The subgraph SHALL contain nodes: `select_cast`, `build_inputs`, `run_simulations`, `validate_projections`, `synthesize_plan`.

The `run_simulations` node SHALL use LangGraph `Send` API to fan-out N parallel actor simulation tasks and aggregate results.

#### Scenario: Actor Simulation subgraph with multiple NPCs

- **WHEN** `select_cast` node returns 3 NPCs
- **THEN** `run_simulations` fans out 3 parallel LLM calls via `Send`, aggregates results, and `synthesize_plan` produces a unified director plan

#### Scenario: Actor Simulation subgraph with no candidates

- **WHEN** `select_cast` node returns empty candidate list
- **THEN** subgraph routes to `END` immediately with `simulationCount: 0`

### Requirement: DM Agent tool loop is defined as a LangGraph agent graph

The DM Agent orchestration SHALL be implemented as a LangGraph graph using `ToolNode` with a conditional agent loop.

Existing hard constraints SHALL be preserved: maximum 2 tool-calling rounds (3 absolute upper bound), total budget 30 seconds, per-tool timeout 3 seconds.

When `hasPlan` is `true`, the agent's system prompt SHALL include the `directorHintBlock` as directional guidance.

#### Scenario: DM Agent invokes tools then produces narrative

- **WHEN** agent node decides to call 1 read-only tool
- **THEN** graph routes to tools node, executes the tool, routes back to agent node, which produces final narrative and routes to END

#### Scenario: DM Agent exceeds round limit

- **WHEN** graph reaches round 3 (absolute limit)
- **THEN** graph forces route to END regardless of pending tool calls

### Requirement: Feature flag gates LangGraph adoption

The system SHALL provide a `VERSECRAFT_ENABLE_LANGGRAPH` environment variable (default `false`) that toggles between the LangGraph orchestration path and the existing manual pipeline.

When disabled, all existing tests SHALL pass without modification.

#### Scenario: Switch off uses legacy pipeline

- **WHEN** `VERSECRAFT_ENABLE_LANGGRAPH=false`
- **THEN** `runWorldEngineTickLegacy()` executes, and all existing unit/contract tests pass

#### Scenario: Switch on uses LangGraph pipeline

- **WHEN** `VERSECRAFT_ENABLE_LANGGRAPH=true`
- **THEN** `runWorldEngineTickGraph()` executes via compiled LangGraph StateGraph

### Requirement: World Director graph emits LangGraph node analytics events

When the LangGraph path is active, the system SHALL emit `world_engine_langgraph_node` analytics events for each graph node execution.

Each event SHALL include: `node_name`, `duration_ms`, `status` (`ok` | `error` | `skipped`), `tick_id`, `hasPlan`.

#### Scenario: Node execution emits analytics event

- **WHEN** the `run_reasoner` node completes successfully with `hasPlan: true`
- **THEN** a `world_engine_langgraph_node` event is recorded with `node_name: "run_reasoner"`, `status: "ok"`, `hasPlan: true`

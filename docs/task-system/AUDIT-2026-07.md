### 1.2 §3.2 缺陷逐条核查

#### #1 终态可复活 ✅ 确认
- `updateTaskStatus`（`useGameStore.ts:1715-1721`）：`const next = (s.tasks ?? []).map((t) => t.id === taskId ? { ...t, status } : t)` — 无守卫，completed/failed/hidden 可被任意新 status 覆盖
- 奖励有幂等账本（`appliedRewardTaskIds`）防重复发钱，但关系后果/UI 状态不幂等

#### #2 addTask 合并覆盖终态 ✅ 确认
- `addTask`（`useGameStore.ts:1704-1710`）：同 id 走 `applyTaskUpdateToTask` 全量合并
- `normalizeStatus`（`taskV2.ts:316-320`）：缺省返回 `"active"` 
- 组合效果：DM 重发已完成任务的 id 即把状态刷回 active

#### #3 未知 id 静默吞 ✅ 确认
- `updateTask`（`useGameStore.ts:1727-1729`）：`.map(t => t.id === patch.id ? applyTaskUpdateToTask(t, patch) : t)` — 找不到 id 原样返回
- 无 flag、无遥测、无模糊匹配

#### #4 无活跃上限 ✅ 确认
- 全库无 `MAX_ACTIVE_TASKS` 常量
- 开局 `createStageOneStarterTasks()` 种入 12-13 条（初始可见 2 条，其余 hidden 链式解锁）
- 唯一上限是 `MAX_NEW_TASKS_PER_TURN=3`（`resolveDmTurn.ts:37`）

#### #5 时限装饰性 ✅ 确认
- `autoFailAfterGameHour` 已接线于 `useGameStore.ts:2058`（`applyAutoFailedTasks`）— 但全部 starter 任务无一设置该字段
- `expiresAt` 仅展示；prompt 从未指示模型输出 deadline 格式
- change_set 的 `time_pressure` 只进 `security_meta` 元数据
- 「机会·限时」卡纯装饰

#### #6 完成检测全押 LLM ✅ 确认
- `completionDetector.ts` 死代码，零生产引用
- `validateNarrative.ts:604` 的 `task_mode_mismatch` — severity=low，仅遥测无修复动作
- DM 不 emit `task_updates` → 主线永不推进

#### #7 四轴语义打架 ✅ 确认
- `status`（5 值）：active/completed/failed/hidden/available
- `grantState`（6 值）：discovered_but_unoffered/narratively_offered/accepted_in_story/visible_on_board/soft_tracked/archived_hidden
- `QuestState`（死代码 7 值）：locked/available/active/deliverable/completed/failed/expired
- `surfaceClass`（4 值）+ 派生 `TaskVisibilityTier`（`taskVisibilityPolicy.ts:36-61`，混用两轴+白名单）
- 无单一事实源

#### #8 迁移裸透传 ✅ 确认
- `migratePersistedState`（`useGameStore.ts:242`）对根级 `tasks` 走 `...raw` 原样透传
- 本次授权不管兼容，但旧存档需保证不崩

#### #9 结算无视任务 ✅ 确认
- `src/lib/settlement/rules.ts`：零 task 引用
- 结算页只把未完成任务当「重玩钩子」展示
- 任务完成度对结局毫无影响

#### #10 世界引擎不推进任务 ✅ 确认
- `src/lib/worldEngine/agenda.ts`：零 task 引用

#### #11 命名碰撞 ✅ 确认
